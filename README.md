# Encarta 95 on the web!

Run **Microsoft Encarta 95** entirely in the browser via
[v86](https://github.com/copy/v86), served as a static site. A pre-booted Windows 95
snapshot loads straight into a live, interactive Encarta; the Windows hard disk and the
Encarta CD are streamed on demand.

Play here -> https://benwinding.github.io/encarta_95_web

## Requirements

- Node.js + npm
- The **Encarta 95 CD** (`encarta-95.iso`) — you supply it.

  - Download: <https://archive.org/details/msencarta95>
  - Expected: `675,440,640` bytes, md5 `02f8dc508c4abaf0202af51c66ee2cb0`

## Setup

```sh
npm install
mkdir -p input
cp /path/to/encarta-95.iso input/encarta-95.iso   # or set ENCARTA_ISO=<path>
npm run build
npm run run      # http://localhost:8080
```

Then open <http://localhost:8080>, click the screen to capture the mouse, and use Encarta
(search, links, **Features → Mind Maze**, …).

**Desktop:** the page captures the mouse via Pointer Lock — the host cursor is hidden and
the guest cursor follows input 1:1.

**Touch:** tap a point to warp the guest cursor there and click; drag to move the cursor. A
floating keyboard button opens the on-screen keyboard (with a bridge for
Enter/Backspace/Tab/arrows). The Windows 95 taskbar is visually masked, and desktop escape
keys (Alt+F4/Alt+Tab/Ctrl+Esc) are suppressed.

Touch uses the relative PS/2 mouse: there is no absolute-mouse driver for Windows 95
(VBADOS/VBMOUSE target Windows 3.x, and its `VBMOUSE.DRV` crashes the Win95 boot). The page
keeps a host-side model of the cursor position (a packet of `n` mickeys moves exactly
`2n` px — Win95's default pointer speed, clamped at the borders), so a tap moves the cursor
straight to the tapped point and clicks, with no visible corner detour. v86's PS/2
controller consumes only one mouse packet per browser event-loop turn (bursts are dropped),
so packets are sent one at a time, waiting for the guest to read each. Once at load (the
cursor ends up centred) and once at the start of each drag, the model re-syncs by slamming
the cursor into the top-left corner to re-learn its origin.

## Commands

| Command | Does |
|---|---|
| `npm run build` | copies the emulator into `public/runtime/` and splits your ISO into 256 KB parts in `public/disks/encarta95/` |
| `npm run run` | serves `public/` on <http://localhost:8080> |

## Structure

```
public/                 # static web root (served)
  index.html            # the app: boots v86 + restores the snapshot
  title-map.js          # media caption -> article title map (generated from the ISO)
  runtime/              # libv86.js + v86.wasm        (generated by `build`)
  bios/                 # seabios.bin, vgabios.bin    (tracked)
  state/encarta95.bin.zst # pre-booted Win95+Encarta snapshot, zstd (tracked)
  disks/
    c-drive/            # Windows 95 hard disk, 256 KB parts   (tracked)
    encarta95/          # Encarta CD, 256 KB parts             (generated from your ISO)
input/                  # your supplied ISO(s)                (gitignored)
vendor/                 # patched v86 build + source patch    (tracked)
scripts/                # build tooling
```

## How it works

- **v86** boots a Windows 95 disk (`disks/c-drive`) with the Encarta CD mounted (`disks/encarta95`).
- A **RAM snapshot** (`state/encarta95.bin.zst`) restores directly into a running Encarta — no cold
  boot. It is zstd-compressed (~9 MB instead of ~50 MB); v86 decompresses it natively. Regenerate
  it with `node scripts/compress-state.mjs` after saving a raw `state/encarta95.bin`.
- Both disks are **paged**: only the 256 KB chunks the guest actually reads are fetched.
- Chunks are fetched **synchronously** (`synchronous: true`, using `vendor/libv86.sync.js`;
  source diff in `vendor/v86-sync-xhr.patch`). Windows 95's `ESDI_506` driver aborts
  asynchronous CD reads, so synchronous delivery is required — this fixes crashes on CD
  features such as Mind Maze.
- Article views are **hash-routed** (`#/article/<title>`). The host resolves Encarta's
  current media caption to a canonical/searchable article title; URL-driven navigation
  keeps that title pinned even when the caption is reused by another article.

## Notes

- The Windows 95 hard-disk image and the snapshot are committed — they are a **matched pair**
  (the snapshot only restores against this exact disk). `win95.iso` is therefore not needed.
- HTTPS is not required: v86 runs single-threaded, and static hosts without `COOP`/`COEP`
  (e.g. GitHub Pages) work fine.
- `RESEARCH.md` has the background research on approaches and risks.
